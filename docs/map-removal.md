# Карта инцидентов: план удаления

**Статус:** карта скрыта, но код не тронут. Главный экран — «Обзор» с четырьмя группами из ТЗ. Карта открывается
яркой кнопкой «Карта» в шапке (клавиша `G`). Кнопка намеренно заметная: на время перехода карта должна быть под рукой.

## Почему карту нужно убрать

1. **В данных нет координат.** В выгрузке ITSM (`data/incidents_attributes.json`) нет ни координат, ни региона, ни
   адреса. Сейчас сервер ставит инциденты условно: каждый продукт привязан к «своему» городу, инциденты разбросаны
   вокруг него (`placeOf` в `server/source-file.ts`). Точки на карте ничего не говорят о том, где на самом деле сбой.
   В легенде это не подписано: карту по просьбе команды оставили в исходном виде.
2. **ТЗ требует работать только с форматом файла.** В слайде «Требования и ограничения» сказано, что дашборд работает
   только с тем форматом, который представлен в файле с инцидентами. Условные точки и пустые поля `crew` и `path`
   в модели — выдуманные данные.
3. **Мёртвые возможности.** Бригады в пути (`crew`) и оборванные магистрали (`path`) жили только в симуляторе. Симулятор
   удалён, в выгрузке таких полей нет, поэтому эти слои карты всегда пустые.
4. **«Лёгкий, не перегруженный интерфейс»** — один из пяти критериев оценки в ТЗ. Карта — самый тяжёлый экран: внешние
   тайлы, анимация на `requestAnimationFrame`, около 0,8 МБ кода `maplibre-gl` в бандле. Координатору она не помогает
   решить, кому передать инцидент и не сорвётся ли срок.
5. **Зависимость от интернета.** Подложка грузится с `basemaps.cartocdn.com`. В закрытом контуре (а у дежурной смены
   он, скорее всего, такой) карта покажет пустой фон.
6. **Старая логика групп.** Фильтр-кнопка «P1–P2» на карте ведёт в группу «Критические», которая теперь означает только
   приоритет «Наивысший». Подпись неточна, но по договорённости код карты не меняли. Кнопка «Разобрать с ИИ» скрыта:
   массового назначения больше нет, назначения вносятся в ITSM.

## Когда карту стоит вернуть

Если в выгрузке появится поле с местом сбоя: регион, площадка, ЦОД или координаты. Тогда карту нужно переделать
на реальные поля, а не возвращать условную расстановку.

## Что удалить

| Что | Где |
|---|---|
| Экран карты | `src/components/MapView.tsx`, `src/components/MapCanvas.tsx` |
| Кнопка и клавиша `G` | `src/components/TopBar.tsx` (`.map-toggle`), `src/App.tsx` (ветка `view === 'map'`, обработчик `g`), `src/components/HelpOverlay.tsx` |
| Вид `map` | `src/store.ts` (`View`) |
| Стили | `src/styles.css`: блок «Карта», `.pills`, `.pill-f`, `.urgent`, `.ticker`, `.legend`, `.sheet-float`, `.map-toggle` |
| Поля модели | `shared/types.ts`: `geo`, `region`, `crew`, `path`, типы `GeoPoint`, `Crew` |
| Условная расстановка | `server/source-file.ts`: `CITIES`, `hash`, `placeOf`, поля `crew`/`path` в `mapRecord` |
| Упоминание в карточке | `src/components/IncidentSheet.tsx`: строка «На карте: … расположение условное» |
| Зависимость | `package.json`: `maplibre-gl` |

`IncidentCard` из `src/components/Board.tsx` карта не использует: её левая панель — собственная разметка внутри
`MapView.tsx`. Поэтому после удаления «Обзор» и очередь продолжат работать без изменений.

## Как проверить после удаления

```powershell
npm run typecheck
npm test
npm run build
```

Затем открыть дашборд и проверить: «Обзор», «Очередь», «Продукты», «Лента», карточку инцидента, кнопку «Открыть в
ITSM» и реакцию на правку файла (`npm run demo -- critical`).
